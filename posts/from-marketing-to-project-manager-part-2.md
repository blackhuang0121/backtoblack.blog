承接上一篇 - [「B2B 行銷」到「品牌會員經營」再到「軟體系統導入專案經理」的轉職之路（序）](https://backtoblackblog.vercel.app/posts/from-marketing-to-project-manager-part-1)，感謝過去的自己拉了自己一把，接下來就是面試了——即使對於 PM 工作的想像、技術的理解還有些不踏實，也找了之前上程式課的老師聊聊，針對既有程式能力之於軟體工程師職涯的看法。

「總之先都丟丟看吧，有面試機會就去聊聊，或許近一步了解後，發現其實程式開發的工作與你所想像的職涯規劃有落差。也不是一定要擔任工程師才能將活用近一年所學的技術內容。」—— 老師給了我這樣的回饋。

## 有些事要實際面試了才會知道

帶著些許不安的心情開始看相關職缺，主要鎖定在`技術相關專案經理`、`軟體前端工程師`兩大類：
1. 技術相關專案經理 - 考量到過去較少直接參與產品開發的經驗，過去也僅有在負責 B2B 行銷時，參與一小段時間協助產品文件的撰寫，因此決定**鎖定系統整合、軟體導入，或是軟體開發職能的專案經理作為主要目標**，試著將之前與系統商專案經理協作的經驗，嘗試實際擔任團隊與客戶間的溝通與交付的窗口：
    a. 產業：以熟悉的軟體科技產業為主，也試著投遞傳統科技產業，另外金融業近年也有很多數位轉型專案、系統導入的需求，所以也將金融業納入選項。
    b. 職稱：軟體科技業的`軟體專案經理`、`專案管理師`等職缺，皆期待此角色能直接與客戶窗口（甚至是 IT 部門）對接開發需求與時程，有效協調內部開發資源，確保資源被準時、正確交付，甚至在專案前期就會與業務協作，依照情境收斂需求，對於技術的了解有一定要求；不論是科技業的`軟體管理師`，還是金融業的`數位轉型專案規劃人員`，搭配職能的描述，似乎更期待此角色聚焦在專案時程的控管，以及整體內部資源的調節，在較長期的專案過程中，與各司其職的團隊協作，直接參與開發的機率不高。

2. 軟體前端工程師：依照目前所累積的開發能力，也參考老師分享的軟體工程師職涯發展內容，主要投遞品牌端 Junior 的前端開發工作，暫不考慮接案的乙方（不喜歡免洗的工作環境，我也不是非轉工程師不可——只有投遞一家乙方的實習機會，因其網頁設計服務風格很吸引我，且提供實習後依表現機會轉正的機會，不過後續獲得無聲卡ＱＱ）。
    a. 產業：以軟體科技產業為主，
    b. 職稱：`Frontend Engineer`、`前端工程師`、`Software Engineer`的職缺強調能不能熟悉目前的開發語言、開發框架，以及對於 CI/CD、報錯的機制的理解，因此熟悉多種語言，與至少一種現代的開發框架是基本能力。

## 一切都是過程，都是最好的安排

![（DSCF2847.JPG）](/img/BlogSwitchCareer/DSCF2847.JPG)

投遞工程師的職缺如預期般的不順利（笑

僅有從一家提供金融財報分析的新創軟體公司獲得前端工程師的面試機會——團隊不大所以沒有 Coding 關，總共只有兩面（一面：HR、二面：創辦人暨技術長）。線上一面我賣力以部落格專案的內容作為開發專案主題，從使用語言、開發架構到過程中遇到的問題如何排解著手，逐一呈現前端 UI/UX 使用到的功能，也分享了從行銷到接觸程式的心路歷程，以及對於開發的理解。

不過隔了一週，還是收到了感謝信，沒有機會與創辦人聊聊。「應該是需要使用即戰力吧...」——我這樣想。

其他投遞的職缺多半是無聲卡，少數幾家有收到 Coding 作業，但看過題目才深感自己對於程式的底層邏輯理解實在太低，對於半路出家，也不打算經歷乙方免洗鍛鍊的我實在太困難了——即使有過去一年的學習，以及數個小專案的開發，對於整體開發時程，以及如何透過技術解決商業問題有一定的理解，追根究底**隨著專案 scope 的提升，複雜性是呈指數增長**，但`在沒有太多程式理解的情況下，就透過 AI Agent 協助的開發經驗，說白了與現職工程師依照情境與 Claude Code 協作產出程式有本質上的不同，現階段實在難以以品牌端工程師的身份，即時、正確的進行開發/排除 bug`。

總結投遞前端工程師對於自己來說應該是：
1. 再更具體了解工程師在團隊扮演的角色。
2. 釐清現階段對於程式的理解程度在哪。

PS 時間快轉了半年到今（2026）年初，我已經在現職公司擔任軟體導入的 PM，某次與以前同事聚餐時，被問道「你是不是有面試一家新創公司叫做 XXX？」，我回想片刻才回想起這件事，也才想到這位同事跟創辦人應該是大學同學關係——她說後來創辦人向她聊到我，也回饋到其實我**充分展現對需求導向而開發、團隊協作的理解，在分享專案的過程中也展現積極的 Growth Mindset，學習的方向也是正確的，唯一可惜的是公司在那時太需要如即戰力協助產品開發，團隊也沒有 Mentor 可以帶領**，所以後續才沒有繼續推進我。

聽完的當下我超開心，自己過去幾年的努力沒有白費，獲得第一線的程式工作者的肯定，即使現在換了個身份，從工程師到專案經理，但學到的相關知識也實際應用在現職的工作上，也因此更肯定自己之於目前的職涯方向。

## 上岸——從行銷到專案經理

面試專案經理的過程中面了一家從負責 Deliver 品牌各種客製化需求的軟體公司提供的軟體專案經理職缺。安排面試只有安排一關，由用人主管面完後決定人選（即使他有提到應該需要補一個以上，但 Headcount 高機率只能有一個）。面試過程中，`有沒有 Data layout`、`誰打 API`、`更新頻率`等用詞不斷被提及，也聊到每次在完成 PRD 後，怎麼依照安排的專案時程與內部工程師協作等細節，回應如**品牌如何透過既有 App，在會員消費出示會員條碼後，將累積的點數同步到會員集點卡上**等問題。

「即戰力的程度應該還是差了一點。」雖然最後還是感謝信，但對於技術專案經理要做的事又更理解了，與自己的認知兩相驗證，也更篤定想轉職的念頭。

PS
1. 轉職過程中其實收到很多行銷相關的面試，才深刻意識到`轉職`不是一件容易的事，平時的準備就不用再多提，實際踏出第一步開始面試後才是考驗的開始——`面試官看起來就像是辯論比賽永遠的反方，一心想挑戰自己，從言談中找到破綻，說服自己撤銷想轉職的念頭`。
2. 行銷的工作只有因邀約而參與一家日商 B2B 軟體公司提供的行銷專員職缺的面試流程——因為過去的經驗所以推進的很順利，但最後一關被刷掉，`積極度的落差果然還是可以在聊天的過程被體現出來，但自己也同時更確信行銷不是下一階段職涯想要做的事`。
3. 雖然是鎖定專案經理的職缺投遞，但也有因欣賞該公司文化、產品的因素而投遞幾間軟體公司、科技公司產品經理的職缺，但高機率因為完全沒有直接的經驗，所以都沒有獲得面試的機會。

最後是現職——某天深夜修完新一版履歷與專案成果後，想說睡前再瀏覽有沒有新的職缺，現職的 JD 就這麼剛好出現在 104 的搜尋結果上。

主要協助品牌完成 CDP (Customer Data Platform) 系統導入——從需求確認、工具評估、導入規劃、專案執行，到最後的成果交付的 end-to-end 流程，看完 JD 的當下就覺得是很難得的機會，過往實際導入系統的經驗應該也能在面試過程加上不少分數。投遞後隔一兩天很快就由 HR Quick call 展開緊湊但不馬虎的面試流程——從一面、簡報關，再到最後的老闆面感受出團隊對於這個職缺的重視，也透過過去的系統導入經驗分享自己做得好跟可以優化的地方，從問答中也獲得很多關於專案經理的回饋。

面試過程`行為面試（Behavior Interview）`也幫了不少忙，尤其是透過前輩分享的架構進一步優化自己的行為面試題庫，著實是乾貨滿滿——[行為面試(BQ)準備大全！錄取 Amazon 的面試心法大公開｜內附常見問題與 Sample Answers](https://nolliechy.medium.com/%E8%A1%8C%E7%82%BA%E9%9D%A2%E8%A9%A6%E6%BA%96%E5%82%99%E5%A4%A7%E5%85%A8-%E9%8C%84%E5%8F%96-amazon-%E7%9A%84%E9%9D%A2%E8%A9%A6%E5%BF%83%E6%B3%95%E5%A4%A7%E5%85%AC%E9%96%8B-%E5%85%A7%E9%99%84%E5%B8%B8%E8%A6%8B%E5%95%8F%E9%A1%8C%E8%88%87-sample-answers-d1209fd6ce73)，從過往有關`團隊合作`、`問題解決`、`壓力管理`、`自主學習`、`創新經驗`的經驗作為故事內容，實際面試時再透過 `STAR 原則（Situation, Task, Action, Result）`在有限的時間表達被問到的 2-3 個行為面試題，並針對其中至少一個題目進行 Dive in 準備，剩下的結果就順其自然了。

相比工程師聚焦在程式開發，以`專案經理`作為職涯下一站更適合現階段的自己，`每一次客戶的需求會因為其團隊組成、時程、預算，甚至是資安與效能的考量而有所不同，很多時候還需要透過我們去收斂其需求，最後再調整交付使用的技術 scope`，某種程度這樣多維度平衡的評估更具挑戰性，也是專案經理串連起客戶與內部團隊協作順利的價值。而在`科技與 AI 發展迭代速度加速的現在，專案的啟動容易許多，專案管理的需求相對的被放大，本身的價值更顯重要`。

## 實際上工心得與下一步

加入現職已超過半年，實際獨立負責系統導入也超過一季，陸續完成了數家新客導入的專案，橫跨了既有台灣三大電商（91APP, SHOPLINE, CYBERBIZ）的系統對接，雖然還沒有接觸較爲複雜的自架系統對接情境，但在協助Pre-sales 情境梳理、收斂需求這段，已經有針對自架系統對接的評估了，針對評估有客製化開發的需求，也提供 PM 評估結果用以估計人天。回過頭檢視也達到入職時設定的目標：
1. ✅ 短期：熟悉公司導入流程，以及導入對應的系統操作情境。
2. ✅ 中期：至少分別完成一次三大電商系統客戶的導入交付，能即時依照客戶需求，搭配對於程式開發的理解，從情境回推技術需求回應 Pre-sales 內容（`重點是怎麼樣回應顧客期待，以最有效率方式推進`）。

另外也引入 Notion 作為組內專案管理表、相關文件/流程/規格表管理的工具使用，與 AM 協作提升系統導入的專案管理效率。

> 「我覺得你做得很好，沒什麼問題。」

近期與主管 1-on-1 時候，被實際肯定對於`專案與系統導入日常工作細節的掌握度——始終能從專案任務的細節回推需求，思考「為什麼要做？」、「如何能更有效率」，也能「跨任務，甚至是跨專案思考是否會有錯誤連動影響的可能性」`...以上第一手回饋真的給予自己很大的肯定，也期許自己接下來繼續以專案經理的身份：

1. 保持專業、保持熱忱地面對接下來可能的自架客戶導入專案：
2. 以自架客戶的導入標準更熟悉技術，e.g., API 測試流程、理解 API 文件與規格，能與工程師、PM 更有效協作：不僅是開發需求，Bug 處理更是。

以上也都規劃與 AI Agent 的建置緊密協作，目標在年底 drive 出最高效率，以便能更專注需求端的收斂，將價值即時 Deliver 給客戶。長期若有機會，也希望能開始了解 Product Manager 的工作內容，帶著實際與客戶對接的經驗，我相信對於產品 roadmap 的開發也會很有幫助。
